CodeAgent 实现方式对比

选项 1: 保留 BaseExecutor 继承结构

实现方式

from src.core.orchestration.registry import agent_registry
from langchain.agents import create_agent
from langchain.tools import tool

@tool
def read_file(path: str) -> str:
    """读取文件内容"""
    with open(path, 'r') as f:
        return f.read()

@tool

    # 执行逻辑...

# CodeAgent 继承 BaseExecutor
@agent_registry.register(
    name="code_agent",
    description="处理代码相关请求",
    keywords=["代码", "编程"],
    command="@code"
)
class CodeAgent(BaseExecutor):
    async def run(self) -> List[BaseMessage]:
        # 在 run 方法内部使用 LangChain create_agent
        tools = [read_file, execute_code]
        agent = create_agent(llm, tools)

        # 构建消息（使用基类方法获取上下文）
        messages = [
            SystemMessage(content=prompt),
            *self.get_context_messages(),  # ← 使用基类方法

        # 调用 agent 而非直接调用 llm
        result = await agent.ainvoke({"messages": messages})

优点
  • 保持与现有架构的兼容性
  • 复用 BaseExecutor 的 get_context_messages() 方法
  • 不改变 MasterWorkflow 的调用方式
  • 渐进式改造，风险低
缺点
  • 混合架构风格（自研 + LangChain）
  • 无法充分利用 LangChain 的 Runnable 接口特性

选项 2: 完全 LangChain 化 (Runnable 接口)

什么是 LangChain Runnable 接口？

LangChain 的 Runnable 是一个统一接口，所有组件（LLM、Chain、Agent、Tool）都实现这个接口， 支持 invoke()、ainvoke()、stream()、astream() 等方法。

实现方式

from langchain.agents import create_agent
from langchain.tools import tool
from langchain_core.runnables import RunnableConfig

# 不再继承 BaseExecutor
# CodeAgent 本身就是一个 Runnable

class CodeAgent:
    def __init__(self, session_store, llm):
        self.session_store = session_store
        self.llm = llm
        self.tools = [read_file, execute_code, ...]
        # 创建 agent（这是一个 Runnable）
        self._agent = create_agent(self.llm, self.tools)

    # 实现 Runnable 接口
    async def ainvoke(self, input: dict, config: RunnableConfig = None):
        # 直接从 session_store 获取上下文
        context = await self.session_store.get_context(input["user_id"])
        messages = self._build_messages(input["message"], context)

        result = await self._agent.ainvoke({"messages": messages}, config)

        # 直接保存到 session_store
        await self.session_store.save(...)

        return result

    # 还可以支持 stream
    async def astream(self, input: dict, config: RunnableConfig = None):
        async for chunk in await self._agent.astream(...):
            yield chunk
优点
  • 纯正 LangChain 风格
  • 支持 stream() 流式输出
  • 可以使用 LangChain 的 Middleware
  • 更容易与 LangGraph 集成
  • 支持 Runnable 组合（| 管道操作）
缺点
  • 需要修改 MasterWorkflow 调用方式
  • 需要重新实现会话管理逻辑
  • 改造幅度大，可能引入新问题

详细对比表

维度 选项 1: 保留基座 选项 2: 完全 LangChain 化
改造范围 仅 CodeAgent.run() 内部 CodeAgent + MasterWorkflow
与 BaseExecutor 关系 继承 不继承，独立实现
会话管理 使用现有 SessionManager 可能需要适配 LangChain Memory
流式输出 不支持 支持 (astream)
Middleware 支持 不支持 支持
LangGraph 集成 需要适配 原生支持
风险等级 低 中

推荐方案

选项 1：保留 BaseExecutor 继承结构

理由：你提到改造目的是"添加工具能力"和"利用 Memory 特性"，这两个目标通过选项 1 就可以实现。 选项 2 的好处主要是为了与 LangChain 生态深度集成（如 LangGraph、Middleware），但这需要更大的改造成本。

关于"需要调整"的部分： 如果你希望引入 LangChain 的 Checkpointer 实现持久化 Memory， 这可以在选项 1 的框架下完成——在 create_agent 时传入 checkpointer 参数即可，不需要改变整体架构。
